# 安全、交接与权限

## 1. 文件系统

- Agent 通过 ACP 请求读/写文件时，LJ Hub 会把路径规范化并检查是否落在**项目目录内**；
  越界一律返回错误（`E_INVALID_PARAMS`），不会放行。
- 校验通过后返回的是规范化路径，避免"检查一个路径、操作另一个路径"。
- 应用自身只读写自己的数据目录（`~/Library/Application Support/com.ljhub.desktop`），
  以及用户显式选择的项目目录。

## 2. Git

只允许只读子命令，白名单写在 `git.rs` 里：

```
rev-parse, status, log, remote, diff, show, branch, ls-files, config
```

`reset`、`clean`、`checkout`、`push` 等一律拒绝（有测试断言）。
所有命令带 `-C <dir>` 执行，不受进程当前目录影响；并设置
`GIT_OPTIONAL_LOCKS=0` 以避免在检查状态时对仓库加锁。

## 3. 权限请求

ACP 的 `session/request_permission` 会阻塞 Agent，直到用户决定。LJ Hub 的做法：

- 请求进入待决表，界面显示选项；同一请求 id 只能被解析一次，
  重复点击不会二次放行（有测试）；
- 用户点"拒绝"、请求超时（10 分钟）、会话中断、应用退出，
  **一律回 `cancelled`**，绝不默认放行；
- 会话结束时把仍未决的请求全部按"未批准"处理。

自动化测试用模拟 Agent 逐字校验：拒绝权限后，Agent 的回复里不能出现"已获得授权"，
Agent 侧记录里也不能出现 `allow-once`。

## 4. 凭据与密钥

- WorkBuddy 凭据只存放于 `<data>/credentials/workbuddy.json`，权限 `0600`，在 `.gitignore` 覆盖范围内；
- 客户端**不内置**任何 `client_secret`；OAuth 授权码换票要么用你自己的本机凭据，
  要么由你自建后端完成；
- WorkBuddy 的 ACP token 不会进入界面、日志或存储（有测试断言序列化结果不含 token 字段）；
- 日志只写 stderr，不含令牌、Cookie、密钥；
- CI 有 `Secret hygiene` 作业，一旦提交里出现疑似凭据或构建产物就直接失败。

## 5. 与你既有 AI 体系的关系

- 既有文档（例如 `USER_REQUIREMENTS.md`、`HANDOFF.md`）只会被**只读**读取：
  显示内容、计算 SHA-256、解析需求列表；
- v0.1 **不会**迁移、覆盖、删除这些文件，也不会在后台与旧协调器争夺工作区控制权；
- 导入的需求在交接资料里以引用形式出现（含来源与状态），原文件不变。

## 6. 任务交接协议

```
PREPARED ──发送方生成资料──▶ VERIFIED ──接收方核验通过──▶ ACCEPTED
                                  └──任一检查失败──▶ REFUSED
```

### PREPARED（发送方）

目标、有效用户要求（含来源）、禁止事项、已完成、重要决策、失败尝试、
Git 证据（根目录 / 分支 / HEAD / 未提交改动）、重要产物（路径 / 大小 / SHA-256）、
尚未完成、下一步行动。

### VERIFIED（接收方核验，五项）

| 检查 | 判据 |
|---|---|
| 工程位置 | 目录真实存在 |
| Git HEAD | 与交接记录的 HEAD 一致，否则报漂移 |
| 工作区状态 | 未提交改动集合与记录一致（对称差集为空） |
| 必要文件 | 登记的产物均存在；有 SHA-256 时内容一致 |
| 资料完整度 | 有目标，且至少有后续行动或待办 |

核验结果会连同 detail 一起写入交接记录，可导出 Markdown。

### ACCEPTED（接手）

- 全部检查通过才写入接受时间与接收方备注；
- 已接受的交接**不能重复验收**（防止两个 Agent 都以为自己是任务拥有者）；
- 原生会话是否恢复单独记录：只有 Agent 声明 `session/load` 且真的成功才算"已恢复"，
  否则明确写"未恢复，但历史仍可阅读"。

### 重要产物的边界

登记记录的是"这个文件当时是什么"，**不是备份**。
`backup_verified` 默认 false，除非你有独立的备份事实。
超过默认哈希上限（2 GiB）的文件不会自动哈希，只登记路径与大小，
需要时用"核验（强制哈希）"按需计算。

## 7. 未做（避免误解）

- 没有沙箱隔离：LJ Hub 不是 OS 级沙箱，它能读写的范围由用户选择的项目目录决定；
- 没有签名与公证：见 README 的构建说明；
- 没有网络暴露：应用不监听任何端口，不开后台服务。
